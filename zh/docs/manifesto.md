# 宣言

Oh My OpenAgent 背后的原则和理念。

---

## 人工干预是失败的信号

**循环中的人（HUMAN IN THE LOOP） = 瓶颈**

想想自动驾驶。当人类不得不接管方向盘时，那不是一个功能。那是系统的失败。汽车无法自行处理这种情况。

**为什么写代码会有所不同？**

当你发现自己：
- 修复 AI 完成了一半的代码
- 手动纠正明显的错误
- 一步步引导代理完成任务
- 反复澄清相同的需求

那不是“人机协作”。那是 AI 没有做好它的工作。

**Oh My OpenAgent 建立在这个前提之上**：在代理工作期间的人工干预从根本上说是一个错误的信号。如果系统设计正确，代理应该在不需要你充当保姆的情况下完成工作。

---

## 无法区分的代码

**目标：代理编写的代码应该与高级工程师编写的代码无法区分。**

不是“需要清理的 AI 生成代码”。不是“一个好的起点”。而是实际的、最终的、生产就绪的代码。

这意味着：
- 完全遵循现有的代码库模式
- 在没有被要求的情况下进行适当的错误处理
- 真正测试正确内容的测试
- 没有 AI 的糟粕（过度工程、不必要的抽象、范围蔓延）
- 只有在增加价值时才添加注释

如果你能分辨出一个提交是由人类还是代理做出的，那么代理就失败了。

---

## Token 成本 vs 生产力

**如果能显著提高生产力，较高的 token 使用量是可以接受的。**

使用更多 token 来：
- 让多个专业代理并行研究
- 在没有人工干预的情况下完全完成工作
- 在完成前彻底验证工作
- 跨任务积累知识

当这意味着 10倍、20倍或 100倍的生产力提升时，这是一项值得的投资。

**然而：**

系统不追求不必要的 token 浪费。系统优化用于：
- 对于简单任务使用更便宜的模型（Haiku, Flash）
- 避免冗余探索
- 跨会话缓存学习成果
- 收集到足够的上下文时停止研究

Token 效率很重要。但不能以牺牲工作质量或人类认知负荷为代价。

---

## 最小化人类认知负荷

**人类只需要说他们想要什么。其他一切都是代理的工作。**

两种方法实现这一点：

### 方法 1：Prometheus（访谈模式）

你说：“我想添加身份验证。”

Prometheus：
- 研究你的代码库以了解现有模式
- 根据实际发现提出澄清问题
- 找出你没有考虑到的边缘情况
- 在你做出决定时记录决策
- 生成完整的工作计划

**你提供意图。代理提供结构。**

### 方法 2：Ultrawork（只管去做模式）

你说：“ulw 添加身份验证”

代理：
- 找出正确的方法
- 研究最佳实践
- 遵循约定进行实现
- 验证一切正常
- 继续工作直到完成

**你提供意图。代理处理一切。**

在任何一种情况下，人类的工作是**表达他们想要什么**，而不是管理如何完成它。

---

## 可预测、可持续、可委派

**理想的代理应该像编译器一样工作**：输入 markdown 文档，输出工作代码。

### 可预测

给定相同的输入：
- 相同的代码库模式
- 相同的需求
- 相同的约束

输出应该是一致的。不是随机的，不是令人惊讶的，也不是以你没有要求的方式“发挥创意”。

### 可持续

工作应该能在中断后继续：
- 会话崩溃？使用 `/start-work` 恢复
- 需要离开一下？进度会被跟踪
- 多天的项目？上下文被保留

代理维护状态。你不需要。

### 可委派

就像你可以把任务分配给有能力的团队成员并信任他们去处理一样，你应该能够委派给代理。

这意味着：
- 明确的验收标准，独立验证
- 出现问题时的自我纠正行为
- 只有在真正需要时才升级（给 Oracle，给用户）
- 完成的工作，而不是“差不多完成了”

---

## 核心循环

```
人类意图 → 代理执行 → 验证结果
       ↑                              ↓
       └──────── 最低限度 ─────────────┘
          (仅在真正失败时干预)
```

Oh My OpenAgent 中的一切都是为了让这个循环工作而设计的：

| 功能 | 目的 |
|---------|---------|
| Prometheus | 通过智能访谈提取意图 |
| Metis | 在歧义变成错误之前发现它们 |
| Momus | 在执行前验证计划是否完整 |
| Orchestrator | 协调工作而无需人类微观管理 |
| Todo Continuation | 强制完成，防止“我完成了”的谎言 |
| Category System | 无需人工决策即可路由到最佳模型 |
| Background Agents | 并行研究而不阻塞用户 |
| Wisdom Accumulation | 从工作中学习，不要重复错误 |

---

## 这在实践中意味着什么

**你应该能够：**

1. 描述你想要的（高层次或详细，由你选择）
2. 如果需要，让代理采访你
3. 确认计划（或者只让 ultrawork 处理它）
4. 走开
5. 回来看到已完成的、经验证的、生产就绪的工作

**如果你不能做到这一点，系统中的某些东西需要改进。**

---

## 我们正在构建的未来

在这个世界里：
- 人类开发者专注于**构建什么**，而不是**如何**让 AI 去构建它
- 代码质量与谁（或什么）编写它无关
- 复杂的项目和简单的项目一样容易（只是需要更长的时间）
- “提示词工程”变得和“编译器调试”一样过时

**代理应该是隐形的。** 不是说它被隐藏起来，而是说它就是能工作。就像电，就像自来水，就像互联网。

你打开开关。灯亮了。你不会去想电网。

这就是目标。
